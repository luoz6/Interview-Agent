# 面试 Agent MVP SDD

## 目标

构建一个最小可运行的面试 Agent 项目，先支持第一条闭环：

1. 用户输入岗位 JD 和简历文本。
2. 系统生成一组面试题目计划。
3. 用户在极简 Web 页面中开始文本模拟面试。
4. 系统提出问题，并根据回答给出确定性的追问。

## 范围

包含：

- 单机本地部署，默认单用户使用。
- 本地 FastAPI 应用。
- 无构建步骤的静态网页。
- 确定性的预热服务，从 JD 和简历中提取简单技术信号。
- 内存版面试会话服务。
- 覆盖核心预热、会话和 API 行为的 pytest 测试。

不包含：

- 真实 LLM 调用。
- 数据库持久化。
- Redis 和 Celery。
- 完整 LangGraph 编排。
- 评分和最终复盘报告。
- 用户登录、用户隔离、跨设备同步，以及面向公网/多用户部署的权限控制。

## 模块

- `app/services/prep.py`：根据 JD 和简历生成题目计划。
- `app/services/session.py`：管理内存中的面试会话和答题流转。
- `app/api/routes.py`：提供预热、开始面试、提交回答等 HTTP 接口。
- `app/main.py`：创建并配置 FastAPI 应用。
- `app/static/*`：最小可用浏览器界面。
- `tests/*`：覆盖预热、会话和 API 行为的测试。

## 功能要求

- `prepare_interview` 对非空 JD 和简历至少返回 3 个问题。
- 当材料中出现技术关键词时，题目计划应包含技术深挖问题。
- 空 JD 或空简历应返回清晰的校验错误。
- 开始面试时应创建会话，并返回第一道题。
- 提交回答后，应记录回答，并返回追问或下一道题。
- Web 页面可以直接调用 API，不需要前端构建工具。

## 设计说明

这个 MVP 用简单模块模拟最终的多 Agent 架构：

- `prep.py` 暂时代替未来的 Knowledge Agent。
- `session.py` 暂时代替未来的 Examiner Agent 和 Orchestrator 状态。
- API 路由保持很薄，只负责请求和响应转换。

后续接入 LangChain / LangGraph 时，应优先替换服务内部实现，而不是重写网页和 API。
