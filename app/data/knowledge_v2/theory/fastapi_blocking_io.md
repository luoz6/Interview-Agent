# FastAPI 异步接口中的阻塞 I/O

## 核心结论
异步路由只有在等待操作能够主动让出事件循环时才有并发优势。同步网络客户端、文件调用或长时间计算若直接运行在事件循环线程中，会让无关请求一起等待，表现为尾延迟突然升高。

## 机制与边界
事件循环在协程遇到可等待操作时切换任务；普通阻塞函数不会自动让出执行权。网络调用应优先使用真正的异步客户端，受控的短同步调用可放入线程池，计算密集任务应转移到进程或任务工作器。线程池只能移动阻塞位置，仍需并发上限、超时和队列容量，否则压力会转化为线程堆积和下游过载。

## 常见错误
给函数增加 async 声明不会把内部同步库变成异步。只看 CPU 平均值也容易漏诊，因为事件循环可能被等待系统调用占住而 CPU 并不高。盲目增加协程、线程或工作进程，可能扩大数据库连接数并放大故障。

## 工程权衡
替换客户端的收益最大，但可能涉及接口改造；线程池迁移较快，却需要考虑上下文传播、取消和线程安全。独立任务队列隔离最好，但会引入异步结果和幂等处理。选择应基于调用时长、频率和用户是否必须同步等待。

## 可观察评分信号
回答应展示事件循环延迟、请求 p95/p99、下游耗时、线程池排队和超时率，并通过受控压测对比修复前后。还应说明失败时如何保留请求语义，以及并发限制如何保护下游。
